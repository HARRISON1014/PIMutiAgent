# 安全、认证与本地数据

## 仓库包含什么

仓库仅包含应用源码、锁定版本的依赖清单、空示例配置、测试代码、文档和已检查的模拟演示截图。npm 依赖在本机安装，不随源码上传。

| 文件或目录 | 本地用途 | 是否纳入版本管理 |
| --- | --- | --- |
| `.piagent/` | 会话数据库、密钥、日志、CLI 请求目录、任务产物 | 否 |
| `.env`、`.env.*` | 本机环境变量和可选 API Key | 否（仅空模板 `.env.example` 例外） |
| `node_modules/` | 本机安装的依赖 | 否 |
| CLI 的认证目录 | 对应厂商账号登录 | 否 |
| 私钥、认证文件、数据库、日志和压缩包 | 可能携带私人数据 | 否 |
| `config.example.json` | 无密钥的角色和连接示例 | 是 |
| `docs/workspace-light.jpg`、`docs/sessions-management.jpg` | 模拟任务界面截图 | 是 |

`.gitignore` 是第一层排除，发布检查还会对 Git 暂存区 / 提交中的实际内容做独立核验，拒绝不在源码允许范围内的文件、认证文件、私钥、常见 token 和带值的示例密钥。检查会在本机比对已保存 API Key / 环境变量的实际值，报告文件名和规则，不打印密钥值。检查工具不会读取或上传官方 CLI 的认证文件。

## 如何在推送前检查

明确选择需要上传的源码文件，加入 Git 暂存区后执行：

```sh
npm run check:publish
```

核验已提交的内容：

```sh
npm run check:publish -- --tree=HEAD
```

检查暂存内容，避免工作区与即将提交的内容不一致。上传新截图前也需要人工确认其中没有密钥、账号、私人任务内容或本机路径。自动检测不能覆盖所有形式的敏感信息。

## 账号登录与运行边界

API Key 可由页面保存到本机 `.piagent/secrets.json`；它是本机明文文件，请按私人数据保护。浏览器不回显已保存密钥。官方 CLI 自行管理订阅 / 账号认证；本项目通过 CLI 使用已有登录，不导出认证文件或复制登录给其他人。

服务仅监听 `127.0.0.1`，校验 Host、Origin 和写请求头。不要将它直接暴露到公网。你选择的模型厂商会接收完成任务所需的提示、项目内容与工具结果；接入模型前应确认你有权发送这些内容。

文件工具保持源项目只读，输出写入独立任务目录。本机命令先由选定风险模型审查并在界面请求本次确认。获准的普通子进程具有当前用户权限，不构成操作系统沙箱。CLI 模式及额外限制见 [适配说明](adapters.md)。

会话归档保留完整记录，可恢复；删除会话永久清除数据库中的对话与执行记录，已经生成的本地产物文件保留。发布源码不包含这些本地数据。
